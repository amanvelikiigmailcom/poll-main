- Путь А (основной): починить доступ в консоль Appwrite (`http://2.135.146.185/`, у пользователя чёрный экран — диагностируется), создать провайдера в UI: Messaging → Providers → Apple, `.p8` + Key ID `4UK954WJMA` + Team ID `5QG4KFTZNJ` + Bundle ID, sandbox ВЫКЛ.
- Путь Б (запасной): расширить скопы ключа — тоже требует консоли.
- После: ID провайдера вписать в прод-`.env` (`APNS_PROVIDER_ID=`), рестарт сервиса, проверка `createPush` тестовому пользователю.
- Готовность: тестовый пуш уходит без ошибок (доставка проверяется на TestFlight).

### 2. Тексты с сервера (свой Remote Config)
- Бэкенд: таблица `content_items` (key/value) + публичный `GET /api/content` + сид дефолтов. Firebase Remote Config НЕ брать (платный сверх 100K запросов/день).
- Приложение: `ContentService` (дефолты в коде, кэш 12ч, never-throws) + перевод ключей волны 1: инвайт, пейволл, апселлы, онбординг, blocked-экран, URL поддержки, флаги `guest_enabled`/`contacts_enabled`.
- Русская инструкция пользователю по правкам в консоли Appwrite.
- Готовность: смена строки в консоли → новый текст после перезапуска; авиарежим работает на дефолтах.

### 3. Онбординг данными
- Страницы онбординга = ключ `onboarding_pages` (JSON: emoji/заголовок/подзаголовок), рендер существующий, fallback — 3 зашитые страницы.
- Готовность: подмена на 5 страниц в widget-тесте; добавление экранов — только правкой в базе.

### 4. Вопросы викторины с сервера в приложении
- Сейчас: бэкенд отдаёт (`/api/quizzes/current`), приложение ходит в локальную банку.
- `QuizService`: онлайн + вход → сервер и голоса в `POST /api/votes`; офлайн/гость — локально как сейчас.
- Готовность: обе ветки покрыты тестами, пуши приходят за серверные голоса.

### 5. E2E на TestFlight (два живых айфона)

- Пуши не тестируются на симуляторе; TestFlight идёт через продакшн APNs.
