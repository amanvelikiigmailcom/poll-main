# Отдельная проверка на iPhone — выполнять вечером / перед релизом

Это **чек-лист ручной проверки реального устройства**, а не уже реализованный автоматический integration_test suite. Обычный `flutter test` его не запускает. Не выдавать наличие этого документа за пройденную проверку SMS/APNs/Universal Links/StoreKit.

## Что запускается без телефона

Из `app/`: `flutter test --no-pub`, затем отдельно `flutter analyze lib test`.
Из `/Users/amanyessen/projects/flyprox_backend`: `npm test`, `node --check src/server.js`.
Это настоящие unit/widget/localhost HTTP-тесты с изолированными внешними провайдерами. Они не используют production-аккаунты и не отправляют SMS/APNs.

## Что потребуется для ручной проверки

- Доступный разблокированный iPhone с доверием к Mac / Developer Mode, если устанавливаем локально подписанную QA-сборку. Xcode Cloud не запускать.
- Отдельные тестовые аккаунты/данные. Нельзя незаметно удалять или переустанавливать основной Flyprox на телефоне владельца: локальный прогресс может потеряться. Установку/очистку данных согласовать перед выполнением.
- Для двухстороннего приглашения — два различных подтверждённых аккаунта. Один Firebase test phone на двух устройствах остаётся одним аккаунтом.
- Подходящая QA-среда/backend, настроенные Associated Domains и подписанный профиль. Текущая публичная версия/старый TestFlight13 не содержат новых приглашений.
- Для покупок — Apple Sandbox. Не подтверждать реальные оплачиваемые покупки.

## 1. Новая установка и онбординг

- [ ] Вход и отдельный гостевой путь работают; отказ от уведомлений не блокирует игру.
- [ ] Возраст до13 блокирует защищённые экраны; допустимый возраст ведёт к контактам/примерам, имени/фамилии/нику и Home.
- [ ] На маленьком экране с клавиатурой кнопки видимы и доступны.
- [ ] Username: назад ведёт к кампусу при школьном режиме и к контактам в контактном; с контактов можно вернуться к кампусу.
- [ ] Во время сохранения username работает назад; при плохой сети появляется ошибка с повторной попыткой, а не бесконечное ожидание.
- [ ] Длинное название кампуса, адрес и Change не перекрываются при увеличенном тексте; возврат сохраняет выбранные кампус/год.

## 2. Сообщения — native Messages

- [ ] До выбора контакта видно объяснение iMessage/SMS, возможной платы оператора и отправки только по Send; заголовок picker — Choose a friend to message (для WhatsApp — Choose a friend for WhatsApp).
- [ ] Нажатие на контакт с одним номером сразу ведёт к готовому сообщению без карточки контакта. При нескольких номерах пользователь сам выбирает нужный; контакт без номера недоступен.
- [ ] В Messages видны выбранный получатель, ссылка и шестисимвольный код; до Send ничего не отправляется. Отдельно проверить iMessage на iPhone и SMS на другой телефон.
- [ ] Отмена picker, закрытие жестом, отмена/ошибка Messages не дают раунд. При v2 результат sent передаётся серверу, и UI показывает только подтверждённый сервером раунд (sent не доказывает доставку); повтор не даёт второй раунд тому же получателю.
- [ ] При недоступном Messages открывается системное меню sharing; награда требует подтверждения получателем ссылки. Копирование приглашения доступно в My invitations.

## 3. Ссылки и код

- [ ] На установленном приложении ссылка из Messages открывает Flyprox при холодном и тёплом запуске.
- [ ] Без приложения открывается страница; копирование выполняется по нажатию; после установки работает вставка/ручной ввод.
- [ ] При отказе во вставке можно ввести код руками. Без нажатия Paste приложение буфер не читает.
- [ ] Ссылка во время OTP/голосования сохраняется, но не разрушает текущий экран и не обходит возрастной гейт.

## 4. Регистрация и один пропуск обоим

- [ ] Друг регистрируется/подтверждает номер, применяет приглашение:один pass каждому, правильный баланс в Profile и Invite friends.
- [ ] Повторный ввод/повтор запроса не дают новых наград; self и существующий аккаунт не получают награду нового друга.
- [ ] Пригласивший получает APNs с first name при разрешённых уведомлениях. Отказ в уведомлениях не мешает получению бонуса через Check invitations/resume.

## 5. Ожидание и сеть

- [ ] После раунда начинается60мин; перезапуск приложения не сбрасывает таймер; Premium не обходит его.
- [ ] Имеющийся pass снимает одно ожидание; если ожидания нет, pass сохраняется.
- [ ] После потери сети/ответа погашение восстанавливается без второго списания; следующий раунд снова начинает60мин.

## 6. Покупки и удаление

- [ ] Sandbox:покупка, отмена, pending, перезапуск и Restore; временная ошибка SDK не отбирает подтверждённый доступ.
- [ ] После Sandbox-покупки проверить серверное право Premium и независимые reveal-квоты (2 full / 5 initial), а не только бейдж в UI. Повтор открытия уже раскрытого голоса не списывает квоту заново.
- [ ] На отдельной согласованной тестовой установке: переустановка → вход тем же аккаунтом → Restore. Доступ и уже потраченные серверные квоты восстанавливаются без новой покупки и обнуления квот.
- [ ] По окончании оплаченного Sandbox-срока, после серверной синхронизации, новые раскрытия недоступны. Ошибка сети сама по себе не должна считаться подтверждённым истечением.
- [ ] Удаление тестового аккаунта завершается только после server success. При ошибке остаётся возможность повторить запрос и локальные данные не стираются преждевременно.

Эти проверки важны перед публичным выпуском новых нативных возможностей, но не нужны при каждом изменении текста/логики. Быстрые автоматические тесты запускать после изменений; устройства проверять отдельным этапом. Результаты фиксировать по каждому сценарию с версией/номером сборки, моделью/iOS и аккаунтами без секретов. До фактического выполнения все пункты остаются непроверенными.
