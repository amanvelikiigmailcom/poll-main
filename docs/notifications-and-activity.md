# Notifications and campus Activity — 24 November 2026

Local implementation; no production migration, worker activation, Superwall webhook registration or new app build has been performed for this release.

## Approved scope

Push transport stays Node backend → Appwrite Messaging → APNs. No FCM sending, new push provider, new Redis instance or dependency change. Existing Firebase SMS login and the client SDK that obtains the APNs token stay in place.

Automations: anonymous new-vote notice, next round after the authoritative **60-minute** wait (including Premium), a verified invitation activation/wait pass, friend request/acceptance, verified Premium renewal and expiry, honest inactivity reminders at 24h/3d/7d, another app-installation sign-in and an actual moderation action. One native review attempt is claimed on the server after a real first received vote; it is an in-app prompt, not a separate push, and Apple may not display it. Existing profile vote counters permit this one attempt for already-selected users.

Next-round and new-sign-in notices cannot be disabled in Flyprox; iOS notification permission still applies. Other preferences default to true and are saved per authenticated account. Inactivity and expiry reminders wait for 10:00–22:00 in the recorded device timezone (UTC fallback). No fabricated counts, rankings, urgency, password-reset advice or claim that an email was sent.

Explicitly excluded: suspicious-activity detection, Terms/Privacy version notices, administrative broadcast UI, repeating broadcasts, removing Firebase Messaging SDK and deploying/migrating Meilisearch. Invitation notification hooks do **not** resume the separately held invitation rollout.

## Private storage and runtime

Six new private tables, no new profiles columns: notify_users (preferences, timezone, activity, review claim, backend UUID), notify_jobs (durable due time/status/attempt/lease), notify_devices (random app-installation IDs), notify_aliases (UUID→account mapping), notify_receipts (sanitized signed billing facts, actual moderation records and source checkpoints), notify_subscriptions (latest verified subscription snapshot/sequence). Account IDs come from bearer authentication, never request userId. UUIDs are generated by the backend, not chosen by clients.

setup-notifications.js is read-only unless --apply. Startup verifies privacy, columns and available indexes; requires NOTIFICATIONS_ENABLED=1, NOTIFICATIONS_SINGLE_WRITER=1, SUPERWALL_PROJECT_ID and SUPERWALL_WEBHOOK_SECRET. Keep NOTIFICATIONS_SCHEMA_READY=1 for deletion when delivery is temporarily off. Use the existing ONE Node process; these locks are not distributed CAS.

The in-process minute worker repairs missed vote/round/friend/moderation hooks from authoritative records, processes billing receipts, then delivers due jobs. Source recovery is bounded to 24h and 100 records/page; the cursor keeps its window while paging. Fixed retention/timer slots avoid accumulating schedules on every app opening. Settings, blocks, relation state, current wait/pass/campus and subscription state are checked again at delivery. APNs requests time out after 10s, retry with exponential backoff up to six attempts; a batch stops after three provider failures. Stable Appwrite message IDs cover retries after lost acknowledgements. `accepted` means accepted by Messaging, not proven device delivery. A failing source-repair stage does not stop already queued jobs.

Account deletion drains user-owned records beyond one page; another user's unrelated records remain. No separate data-pruning scheduler has been installed. The 200-event Activity limit is not deletion of source votes or push receipts; storage retention must be configured explicitly before a large rollout.

## Verified subscription events

POST /api/webhooks/superwall receives the original JSON bytes before express.json. Verify Svix HMAC-SHA256, timestamp ±5min, V2 API version, project/application60567, App Store, bundle where present and premium_pro_weekly. Production ignores sandbox unless separately enabled. Unresolved/old anonymous aliases are ignored, never interpreted as account IDs. Receipts deduplicate provider IDs; latest subscription sequence wins; old renewals do not produce fresh alerts. This handler sends notices and does not grant paid access from client assertions.

Expiry notice is for a currently active subscription with auto-renew disabled and <=24h left; renewal/current state cancels an obsolete warning. The weekly plan's 3-day warning was intentionally replaced by this shorter window. SDK identify uses the server UUID for StoreKit appAccountToken, serializes identity changes and resets aliases between accounts. Existing anonymous subscriptions require actual provider alias resolution; do not guess ownership from a phone or device.

Webhook configuration requires a private Superwall administrative API credential and the endpoint's separate signing secret. CLI OAuth was unavailable in this session; checked project .env, ~/envs/global.env and backend production .env contain no Superwall/Svix variable names. No secret value was printed. The app's public SDK key is not an administrative API credential. Pending owner-supplied file path/authentication and production approval.

## Campus Activity

Settings → **Activity** uses the existing blue/light Flutter design and English text. A card shows chosen person's name, English question, **From a student graduating in 2028** when known, and relative time. It does not expose voter ID/name, phone, gender, class or premium-reveal data. The cohort hint is the voter's graduation year; no guessed grade.

GET /api/activity requires a bearer session, derives campus from selected enrollment and returns **20** cards. The app requests the next page only when scrolling down near the end; initial rendering/pumping does not prefetch pages. Maximum200 events per traversal. Server reads bounded indexed pages (21 metadata rows/lookahead), filters both-direction blocks and removed accounts, and hydrates visible cards. HMAC cursors bind authenticated user, campus, position and consumed count; client userId/campusId/limit cannot expand the audience or bypass the cap. Cursor keys are process-local, so restart or campus/account change requires refresh (409); client clears stale cards and retries from the first page. Retry preserves current cards after an ordinary network error. Signed-out and unselected-campus users see honest explanations.

One additional private table activity_events stores IDs and a snapshot graduation year/time, indexed by campus+time, voter and winner; internal source checkpoint is also private. setup-activity.js is read-only unless --apply. ACTIVITY_ENABLED=1 and ACTIVITY_SINGLE_WRITER=1 start one in-process recovery worker. Keep ACTIVITY_SCHEMA_READY=1 for deletion if display is switched off. Source is completed rounds, recovered by their update timestamp so early votes are not lost while a round is still active. School-mode rounds carry an authoritative campus snapshot. Contact/legacy votes qualify only when both participants have the same selected campus and both enrollment update timestamps precede the vote: a later campus selection/change cannot manufacture historic activity. Missing timestamp proof means omission. Whole-round draft hooks call the committed round-notification-hooks.js after successful submission for immediate projection; the independent completed-round worker works with existing production rounds and repairs interrupted hooks. Original votes are retained; deleting an account erases events where it was voter or winner.

## Campus availability without an admin panel

Catalog uses country, region (US state name), city. New school_location index is country+region+city. Existing school_region index remains. content_items.campus_access_policy holds a validated atomic allowlist. No policy means all catalog locations remain open; invalid/duplicate policy fails closed. Both search-before-pagination and new enrollment enforce it; existing chosen campuses remain enrolled.

Read-only examples in backend repo: `node scripts/campus-access.js --show`; `--locations --country US`; `--country US --region California`; `--country US --region California --city "Los Angeles"`. Add --apply only after confirming the actual restriction. --add adds another region, --all reopens all, --close-all closes new selection. CLI resolves real canonical catalog labels and previews matched campus count; no specific region has been closed in this session.
